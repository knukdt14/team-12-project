# YOLO11n vs YOLO26n 비교 (2026-08-03)

## 배경

기존 배포 모델(YOLO11n, `runs/train_3`)의 Recall이 낮아(0.537) 개선 여지가 있어 보여, 같은 연산량대의 차세대 아키텍처인 YOLO26n으로 비교 실험을 진행함.

- 두 모델 모두 **동일한 학습 조건**: 데이터(`data/train`, 옛 분할 기준 15,210장), epochs=50, imgsz=640, batch=16, seed=42
- YOLO26n은 21/50 epoch에서 중단 (성능 개선 추세가 이미 뚜렷해 조기 종료 판단, patience 조기종료 조건에는 도달하지 않음)

## 동일 epoch(21) 기준 비교 — 신뢰 가능한 결과

같은 학습 데이터, 같은 epoch 수에서 두 아키텍처를 비교한 값. 이 프로젝트에서 가장 신뢰할 수 있는 비교 지표.

| 지표 | YOLO11n (epoch21) | YOLO26n (epoch21) | 차이 |
|---|---|---|---|
| Precision | 0.542 | 0.523 | -3.5% |
| Recall | 0.458 | **0.519** | **+13.4%** |
| mAP50 | 0.495 | **0.517** | +4.5% |
| mAP50-95 | 0.242 | **0.258** | +6.6% |

**해석**: YOLO26n이 mAP50, Recall, mAP50-95에서 우세. 특히 Recall이 크게 개선됐는데(+13.4%), 불량 검사 태스크에서는 미검출(False Negative) 방지가 더 중요하므로 실질적으로 의미 있는 개선.

## 학습 속도 비교

| | YOLO11n | YOLO26n |
|---|---|---|
| epoch당 평균 시간 | 약 146초 | 약 231초 (1.6배 느림) |
| 아키텍처 | 182 layers, CNN | 260 layers, NMS-free, C2PSA attention |
| 파라미터 | 2.62M | 2.57M (거의 동일) |
| GFLOPs | 6.6 | 6.1 (오히려 약간 적음) |

같은 연산량(GFLOPs)인데도 실제 wall-clock 학습 시간은 YOLO26n이 더 오래 걸림. 레이어 수가 많고 구조가 복잡해(NMS-free head 등) 이 GPU(RTX 5060 Laptop)에서는 오버헤드가 있는 것으로 보임. 정확도는 epoch당 더 빨리 오르지만, 시간당으로 보면 이득이 상쇄되는 부분이 있음.

## 참고: YOLO11n vs YOLO11n 최종(50 epoch) 비교

| 지표 | YOLO11n epoch21 | YOLO11n 최종(epoch50) |
|---|---|---|
| mAP50 | 0.495 | 0.588 |
| Recall | 0.458 | 0.537 |

YOLO11n도 21 epoch 이후 계속 개선되었으므로, YOLO26n을 50 epoch까지 완주했다면 추가 개선 여지가 있었을 것으로 추정됨(다만 이번엔 21 epoch에서 중단하기로 결정).

## ⚠️ 중요: test_v2(재분할 데이터셋) 검증은 무효

`resplit_dataset.py`로 만든 `test_v2`(1,575장, family 단위로 유출 방지 처리된 재분할 데이터셋)로 두 모델을 재검증했으나, **결과가 오염되어 신뢰할 수 없음**:

| 지표 | YOLO11n (test_v2) | YOLO26n (test_v2) |
|---|---|---|
| mAP50 | 0.892 | 0.816 |
| Precision | 0.880 | 0.782 |
| Recall | 0.851 | 0.770 |

**원인**: 두 모델 모두 **옛 분할 기준의 `data/train`**으로 학습됨. `test_v2`는 옛 train+valid+test 전체를 재섞어 만든 것이므로, `test_v2`에 포함된 이미지 상당수가 두 모델의 학습 데이터에 이미 포함되어 있었음(데이터 유출). YOLO11n이 더 오래 학습해서(50 epoch) 더 많이 암기했기 때문에 YOLO26n보다 높게 나온 것으로 추정 — 이 자체가 유출을 뒷받침하는 정황.

**결론**: `train_v2`/`valid_v2`/`test_v2`로 두 모델을 처음부터 다시 학습해야만 공정한 재검증이 가능함. 현재는 미실시.

### 진단

- **종합 mAP50 0.830은 특정 소수 클래스의 심각한 실패를 평균이 가리는 상태.** 헤드라인 숫자만으로 "신뢰 가능"이라 판단하면 안 됨.
- **Bodypanel-Dent — 사실상 작동 안 함(최우선 조치 필요).** train family 3장, valid 0장, test 1장 — 완전 탐지 실패(P/R/mAP 전부 0). 원본 사진이 3~4장뿐이라 증강으로 200개까지 부풀려도 실제 다양성은 늘지 않음(REVIEW.md에서도 지적됨). **이 상태로 배포하면 이 손상 유형은 100% 놓침.**
- **boot-dent — Recall 0.28로 매우 낮음.** Precision은 준수(0.76)하나 실제 트렁크 찌그러짐의 72%를 놓침. 원본 87장으로 다른 다수 클래스(600장 이상) 대비 부족.
- **Signlight-Damage — Precision 0.61로 오탐 많음.** 데이터 양(194장)도 중간 이하지만, 다른 손상 유형과 시각적으로 혼동될 가능성도 있어 보임.
- **RunningBoard-Dent — family 500장으로 적지 않은데도 평균 이하(mAP50 0.77).** 데이터량보다 판별 자체의 난이도(사이드스텝 특성상 그림자·각도에 따라 애매함)가 원인일 가능성.
- valid_v2(0.881) vs test(0.830) 격차는 정상 범위 — 과적합 징후 없음. 전반적인 학습 방식·파이프라인은 건강함.

### 결론: 신뢰 가능 범위

- **신뢰 가능(실사용 가능)**: 12개 주요 클래스 — 범퍼/도어/보닛/펜더/쿼터패널/루프/헤드라이트/테일라이트/전후면유리/사이드미러
- **신뢰 불가**: Bodypanel-Dent — 데이터 재수집 전까지 탐지 대상에서 제외하거나 "지원 안 함"으로 명시 권장
- **보강 필요(우선순위 순)**: boot-dent → Signlight-Damage → RunningBoard-Dent

## YOLO11n v2 재학습 — 완전한 공정 비교 완성 (2026-08-04)

이전까지 미실시였던 "YOLO11n을 v2로도 재학습"을 진행해 최종 공정 비교를 완성함(`train.py`, run: `train_20260804_0217`, 동일 데이터·동일 50epoch 조건).

### test셋 최종 비교 (완전히 동일한 조건, 유출 없음)

| 지표 | YOLO11n (v2, 50ep) | YOLO26n (v2, 50ep) | 차이 |
|---|---|---|---|
| mAP50 | 0.827 | 0.830 | +0.4% |
| mAP50-95 | 0.706 | 0.707 | +0.1% |
| Precision | 0.820 | 0.835 | +1.8% |
| Recall | 0.803 | 0.796 | -0.9% |

**중요한 발견 — 이전 결론 정정**: epoch21 시점의 부분 비교(위 섹션)에서는 YOLO26n이 Recall +13.4%로 뚜렷이 우세해 보였지만, **50epoch까지 완전히 학습시키면 두 모델은 사실상 동률**입니다. YOLO11n이 오히려 Recall에서 근소하게 앞서고(0.803 vs 0.796), YOLO26n은 Precision에서 근소하게 앞섭니다(0.835 vs 0.820). 초반 수렴 속도 차이가 최종 성능 차이로 이어지지 않았음 — 학습 초반 몇 epoch만 보고 "더 나은 모델"이라 판단하면 안 된다는 교훈.

### 클래스별 비교 (주요 차이만)

| 클래스 | YOLO11n mAP50 | YOLO26n mAP50 | 비고 |
|---|---|---|---|
| Bodypanel-Dent | 0 | 0 | 둘 다 완전 실패 — 데이터 문제(모델과 무관) |
| boot-dent | 0.262 | 0.318 | YOLO26n이 확실히 우세 |
| Sidemirror-Damage | 0.994 | 0.985 | YOLO11n이 근소 우세 |
| RunningBoard-Dent | 0.753 | 0.769 | YOLO26n이 근소 우세 |
| 나머지 12개 클래스 | 대부분 0.01 이내 차이 | | 사실상 동일 |

### 학습 속도 (재확인)

동일하게 50epoch 완주 기준, YOLO26n이 여전히 약 1.6배 느림(이전 섹션 참고). **정확도가 사실상 동일하다면, 학습 속도가 빠르고 생태계가 검증된 YOLO11n이 실용적으로 더 유리할 수 있음.** 다만 YOLO26n의 강점으로 알려진 "CPU 추론 속도"(HF Spaces 같은 GPU 없는 배포 환경에서 중요)는 이번 비교에서 측정하지 않았으므로, 배포 환경이 CPU라면 YOLO26n을 재고할 여지는 있음.

## 결론 및 다음 단계 (최종)

1. **정확도는 YOLO11n과 YOLO26n이 v2 기준 사실상 동률** — mAP50 차이 0.4%p, 실질적으로 유의미하지 않음
2. boot-dent 하나만 YOLO26n이 확실히 우세, 나머지는 근소한 차이거나 동일
3. 학습 속도는 YOLO11n이 유리(약 1.6배 빠름), CPU 추론 속도는 미검증(YOLO26n이 유리할 가능성 있음 — 추후 확인 필요)
4. **배포 모델 선택은 "정확도"가 아니라 "배포 환경(GPU 유무)"과 "학습 속도" 기준으로 결정하는 게 합리적** — GPU 있는 서버라면 YOLO11n(검증된 생태계, 빠른 재학습), CPU 전용(Spaces 무료 티어 등)이라면 YOLO26n 고려
5. Bodypanel-Dent 신규 데이터 수집이 최우선 과제(모델 선택과 무관), boot-dent/Signlight-Damage/RunningBoard-Dent 순으로 보강 필요
6. 최종 체크포인트(YOLO11n v2 `train_20260804_0217`, YOLO26n v2 `train_20260803_1918`)는 16종 재학습 이후 디스크 정리 과정에서 삭제됨 — 수치는 위 표에 보존

> **참고(2026-08-04 이후)**: 위 비교는 모두 Bodypanel-Dent를 포함한 17종 스키마 기준이다. 이후 Bodypanel-Dent가 라벨링 오류로 판명되어 제거되면서(경위는 [DEFECT_CLASSES.md](DEFECT_CLASSES.md), [CHANGELOG.md](CHANGELOG.md) 참고), 배포 모델은 16종으로 재학습한 `runs/detect/runs/train_20260804_1124/weights/best.pt`(test mAP50 0.887)로 교체되었다. 이 문서의 아키텍처 선택 결론(YOLO11n vs YOLO26n) 자체는 여전히 유효하나, 표에 적힌 수치들은 17종 스키마 기준 과거 기록임에 유의.
